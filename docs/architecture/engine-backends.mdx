VECTOR has one engine contract and two implementations. One implementation is a TypeScript reference. The other is a Rust/WebAssembly module. Both get the same immutable `EngineScenario` and return the same `EngineRun`. The deployment manifest selects the backend. The scenario and the user cannot select it.

## Rust/WASM ABI call order

The production module has a small C ABI. The adapter calls the functions in this order: `vector_abi_version`, `vector_max_input_len`, `vector_input_reserve(length)`, `vector_run_json`, `vector_output_ptr` and `vector_output_len`. Admission accepts a maximum of 1 MiB of JSON. It also sets limits on entity, event, route and integration work before the numerical loop starts.
